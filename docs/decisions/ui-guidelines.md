# Decisions: UI guidelines (GPUI)

Why this area is built as it is. Each entry records what was decided, why, and which alternatives lost. The rules themselves are in [UI guidelines (GPUI)](../standards/ui-guidelines.md). Entries are numbered `D-NNNN`, and the numbers are stable.

<a id="d-0007"></a>
## D-0007: Application logic outside views

*Accepted 2026-11-02 · implemented 2026-11-02*

**Decision.** The views live in `src/app/` (formerly `src/mock/`), and demo data in `src/app/demo/` behind `JOVRU_DEMO=1`. Logic that needs no GPUI moves into library modules the views call: `sql` (splitting, normalisation, preview checks) and `query` (a run's state machine). Identifier quoting for previews moves to the drivers' dialect. The rules are in [Structure](../standards/ui-guidelines.md#structure); the result grid became its own cached entity in D-0012.
**Why.** Logic inside views could only be tested through the view, and a second interface (a CLI, an automated check) would have to repeat it. A run was tracked by several booleans; one `RunState` value now drives the footer, gutter and buttons. The dialect is two `Driver` methods with defaults, `quote_identifier` and `relation_name` (PostgreSQL overrides the latter to leave the database out), and `backend::preview_sql` takes the driver. `Cancelling` waits for the driver's outcome because the stopping run may still change data. It was a large mechanical move, done in behaviour-neutral steps (rename, `sql`, `query`, the grid), one commit each, each passing the gate and a visual check; the run state machine has unit tests for every transition, including cancellation and stale results. New logic follows this layout.
**Rejected.** Keeping the layout: logic stays untestable without a window, the `mock` name misleads and the cost grows with every feature. A separate application crate for services: a stronger boundary, but another crate and more wiring for a single front end; library modules are enough for now.

## D-0013: Thin ancestors of frequently notified views

*Accepted 2026-11-07 · partly implemented (the rule and the editor gutter fix are in force; splitting the editor and the explorer into cached entities is not done) · Amends D-0012*

**Decision.** A notified view renders with all its ancestors; for the grid that is `AppView`, `GroupedTabs` and `Workspace` on every hover, scroll and keyboard selection, and clicks and tooltips cost a frame without caches. This is how GPUI works and is accepted. Instead, views on the path stay thin ([rule 6](../standards/ui-guidelines.md#how-gpui-renders-and-what-follows-from-it)). Splitting the editor, the assistant and the explorer into cached entities stays the standard and a known deviation, done when the measured cost of the ancestors justifies it. This replaces D-0012's first validation (a grid interaction renders only `ResultGrid`), which GPUI 0.3.11 cannot meet; the rest of D-0012 stands.
**Why.** Read in GPUI 0.3.11 (`gpui-pre`): `Window::mark_view_dirty` dirties every ancestor, the window root is never cached, a hover style or scroll offset notifies the view that painted it, and a tooltip or a click calls `window.refresh()`. Frame probe in release on the reference machine (Windows 11, i5-13600KF, RTX 4060 Ti), 2026-11-02, 1480 × 920 with the explorer and assistant open: hover, scroll and selection took 4.3–4.4 / 5.2–8.0 ms (p50 / p95) with 1,000 × 15 and 3.6 / 5.0–5.8 ms with 100,000 × 5; with every other region replaced by empty boxes, 2.8–2.9 and 2.0–2.1 ms p50. Re-rendering the workspace's other regions cost about 0.8 ms per grid frame and the explorer and title bar about 0.7 ms more (35–45% of the frame), while `Workspace::render` itself took 0.07 ms. What broke the budget was data-sized work in an ancestor: the gutter split the whole script and counted lines from the start for every statement on each `Workspace` render, which is quadratic: 6.9 / 9.0 ms with 200 statements, 57 ms with 1,000, and the same per keystroke. After the fix, 1,000 statements gave 4.3–4.4 / 5.3–6.3 ms per grid frame and 3.0 ms per keystroke frame; each edit also maps statements to lines once, 0.6 ms with 1,000 statements, next to 1.3 ms of run bookkeeping. Costs left: about 1.5 ms p50 per grid frame for unchanged regions, growing with features in `AppView` and `Workspace`; the explorer is not virtualized for a large expanded tree and has not been measured with a real connection.
**Rejected.** Splitting the editor, assistant and explorer into cached entities now: about 1.5 ms p50 less per grid frame, but a refactor as large as D-0012 on the release branch, and clicks and tooltips gain nothing; frames are within budget once the gutter is fixed. Redrawing hover or selection without notifying the view: GPUI 0.3.11 has no such API, and changing GPUI is a dependency decision. Dropping the cell hover highlight: a UX change that treats the frequency, not the cost, and scroll, selection, clicks and tooltips are unchanged. Keeping D-0012's validation and recording only a known deviation: GPUI can never meet it, and nothing would stop data-sized work in ancestors.
