# Version 0.2.0

Date: November 6, 2026.

Scope additions: November 7, 2026 (M7–M10) and November 8, 2026 (M11).

- **Approval:** Approved for implementation by the maintainer on 2026-11-07
  (every addition below). An ADR an addition needs is still accepted on its
  own before that addition is implemented.
- **Implementation:** The additions M7–M10 were implemented or measured on
  2026-11-07; each milestone's own line says what is left.

Version 0.1.0 delivers the product's core on Windows: connections, SQL, the
result grid, reports, the assistant and telemetry. Version 0.2.0 makes that
core **reliable for daily use**: session state is honest, large operations do
not freeze the window, long work actually cancels, the application has its
own icon, Linux is validated, and the documentation describes the code.
The proposed additions make daily work easier through SQL files, reopening
closed query tabs and explorer favorites, with measured performance.

This document defines **milestones**, not how to achieve them.

If a request expands the scope beyond these milestones, stop and ask the
maintainer.

## Thesis

Daily use without surprises on Windows, with Linux validated, a product
icon and a focused set of productivity features. macOS validation remains
outside this release.

## Outside this release

These items are **not** 0.2.0 milestones:

- Validating macOS
- Restoring report tabs after restart
- A richer SQL editor, including tree-sitter
- Live assistant tools against the server
- Another driver
- Editing data in the grid
- Moving SQL splitting into drivers
- A virtualized command palette
- Automatic read retries
- TD-002: binding `:name` without a PostgreSQL snapshot
- Thin grid ancestors (ADR-0013), unless the results checklist fails in the
  frame probe

## Milestones

A milestone is **complete** when its *Done when* criterion holds. M1–M5
remain the priority; the proposed additions do not replace incomplete
reliability work. Milestone IDs remain stable references. M6 is finalized
after the other milestones so the documentation reflects the complete release.

### M1 — Honest transactions

The user sees whether the tab's session has an open transaction, pending
changes or a failed transaction. The application never silently commits or
rolls back work.

- **Done when:** the displayed state matches the real session state in
  drivers whose protocols allow reading it. Any remaining approximation is
  named in [Technical debt](../technical-debt.md) and the root README, without
  promising guarantees the code does not provide. The live test of `BEGIN`
  followed by `SET TRANSACTION ISOLATION LEVEL` still passes.
- **Status:** Complete on 2026-11-07 (`3f9ac81`, `15aa44d`, `dfee076`).
  PostgreSQL, MySQL and SQLite report the session's real state through a
  pinned SQLx fork ([ADR-0030](../../adr/0030-transaction-state-through-a-pinned-sqlx-fork.md));
  what is still inferred is named in TD-001 and the root README. A lost
  session holding a transaction runs nothing, notices name the rollback,
  report panels keep no transactions, and closing the application asks
  first. `cargo xtask check --full` passed, the `BEGIN` and
  `SET TRANSACTION` live test unchanged. TD-001 stays open until a SQLx
  release has the readers
  ([transact-rs/sqlx#4512](https://github.com/transact-rs/sqlx/pull/4512)).

Reference: [TD-001](../technical-debt.md#td-001--transaction-state-is-not-read-from-the-protocol).

### M2 — Copying without freezing the window

Copying a selection or page as CSV, or another menu format, above the
confirmation threshold does not hold the UI thread while generating text.
The proposed scope extension also covers the full-value inspector's **Copy**
and report panels' **Copy as CSV** and **Copy for a spreadsheet** menus.

- **Done when:** confirmation above 50 MiB remains; text generation runs
  off the UI thread for every path above, with cancellation and progress
  when it exceeds the copy budget in
  [Performance](../../standards/performance.md). Cancellation or failure
  leaves the clipboard unchanged, and copying a full value never silently
  truncates it to the inspector's display limit. The deviation
  in [Results](../../reference/results.md) and N031 in the
  [Behavioral audit](../../research/behavioral-audit.md) are closed or updated
  to state what actually remains.
- **Status:** Complete on 2026-11-07. Grid selections and query pages first
  (`fa97819`); then the value inspector's **Copy** (the whole stored value,
  `copy_as::CopySource::Value`) and report panels' **Copy as CSV** and
  **Copy for a spreadsheet** moved to the same path: `src/app/copying.rs`
  runs every result copy off the UI thread, confirms above 50 MiB, shows
  progress and **Cancel copy** (also `Esc`, a report panel in its notice
  line) past 100 ms, and publishes only a complete, current copy. The
  deviation in [Results](../../reference/results.md#known-deviations) and
  N031 are closed. `cargo xtask check` passed; checked in the application
  on Windows with 100,000-row SQLite results (confirmation, progress, `Esc`
  and button cancellation leaving the clipboard unchanged, a 3 MiB value
  copied whole).

### M3 — Predictable long operations and feedback

Daily use on Windows covers cancellation, formatting, filtering, TLS and
short searches without the deviations that currently get in the way.

- **Done when:**
  - A dedicated shortcut cancels a run, alongside Stop and the confirmation
    shown when an execution shortcut is repeated.
  - Format shows elapsed time after 2 s and can be cancelled.
  - The grid filter does not rebuild the view on every keystroke; rebuilding
    stays within the [Performance](../../standards/performance.md) budget at
    100,000 rows.
  - The active connection shows whether the session is encrypted and warns
    when it uses plaintext.
  - Metadata searches of one or two characters meet the
    [Performance](../../standards/performance.md) budget or clearly indicate
    that searching is running off the UI thread.
- **Status:** Complete on 2026-11-07. `Ctrl F2` stops the run of the tab on
  screen, as Stop does (the maintainer's choice; GPUI 0.3.11 drops
  `Ctrl Break` on Windows). Format's button reads **Cancel format**, with
  the time after 2 s, and stops the formatter before its next statement
  (`format_until`). The grid filter applies after a 150 ms pause: 13.4 ms
  and 14.1 ms per rebuild at 100,000 rows in a release build. The tab shows
  a lock or an amber **Not encrypted** warning beside **Connected** from
  `Session::encryption`, read once when a session opens
  ([ADR-0032](../../adr/0032-session-encryption-reported-by-drivers.md),
  accepted by the maintainer). The explorer's search
  field shows a spinner while a search runs, as the palette does; one- or
  two-character searches remain about 93 ms off the UI thread.
  `cargo xtask check --full` passed (live PostgreSQL 14/18 and MySQL 8.4/9.7
  encryption checks included). Checked in the application on Windows:
  Format cancelled after 2 s, the plain-text warning (PostgreSQL `prefer`
  with a server without TLS) and the TLS 1.3 lock (MySQL), the filter and
  the search spinner; `Ctrl F2` itself was not driven, since the check
  tooling cannot send modifier keys.

### M7 — File-based saved queries

- **Approval:** Approved on 2026-11-07, with decisions D1–D7 recorded in
  [ADR-0031](../../adr/0031-saved-queries-as-sql-files.md), accepted by the
  maintainer the same day. Scope revised the same day: the
  files hold only SQL, a query's title is its file name and tags stay local;
  the metadata header first proposed here was dropped.
- **Implementation:** Implemented on 2026-11-07 and checked in the
  application on Windows the same day (migration and its notice, the
  library with tags and subfolders, Save, Save as, the conflict, a missing
  file and **Locate…**, rename with the safe name shown first, the folder
  in Preferences, closing a tab and the application with unsaved edits,
  recovery after a crash). The check found and fixed: closing a tab with
  nothing to ask crashed the application (a view updated while it was
  being updated); **Locate…** lost the `●` of unsaved edits; a recovery
  file written while a save was under way could outlive it and reopen as a
  *Recovered* tab; rename did not show the safe file name first; files in
  subfolders did not show their folder; Cancel stretched across the
  footer of the choice dialogs; a slow save showed nothing until it ended.
  The 4 MiB limit (D7) fails the frame budget
  ([Performance](../../standards/performance.md#the-editor-with-a-large-sql-file)):
  the maintainer kept it on 2026-11-08 with soft wrap off above 256 KiB,
  and confirmed it the same day with the reference machine's numbers.
  On the reference machine (2026-11-08) a 4 MiB file opens in one frame
  of 54 ms and one just under 256 KiB, still wrapped, in 185 ms; a click
  into a 4 MiB text stalls 97–131 ms, inside the editor component
  ([measurements](../../standards/performance.md#on-the-reference-machine-2026-11-08)). The keyboard shortcuts were
  not driven on Windows (the check tooling cannot send modifiers); on Linux
  (M5) `Ctrl S`, `Ctrl Shift S` and `Ctrl O` were. `jykre::query_files` reads and
  writes the files (UTF-8, line endings and byte order mark kept, atomic
  writes, a change on disk detected by size, time and FNV-1a digest),
  discovers the library's folder, keeps the local `query_library` state,
  the recovery files and the migration; the application opens (`Ctrl O`),
  saves (`Ctrl S`, `Ctrl Shift S`), renames, asks before closing a tab or
  quitting with unsaved edits, and moves the saved queries of
  `workspace.state` to files at start. `cargo xtask check` refuses a
  `query_files` source that names what runs SQL.

Saved queries live as plain UTF-8 `.sql` files in a configurable default
directory. The files are the source of truth for SQL, and a file's name is
its query's title, so the library can be moved, backed up, edited externally
or tracked in Git. The application writes nothing into a file but its SQL.
Tags and connection associations are local to the machine, like the other
local state. The saved-query library becomes a view of these files.

The recovery storage and migration design are in ADR-0031. Current persistence behavior
remains documented in [Persistence](../../reference/persistence.md) until an
approved change is implemented.

- **Done when:**
  - A default queries directory is available without setup, for example
    `Documents/Jykre Studio/Queries` through the operating system's document
    location. The user can change it, including to a Git working directory,
    and open or save files outside it through system file dialogs. Changing
    the directory never silently moves, overwrites or deletes existing files.
  - **Save** and **Save as** provide one file-based saving flow. The first
    save chooses a file, starting in the configured directory; later saves
    update that file. Saving a query to the library uses this same flow.
  - The library discovers `.sql` files in the configured directory and
    obtains SQL and titles (file names) from the files. SQLite may retain
    file references, tags, tab order, execution context and local connection
    associations; it is not a second store of saved-query SQL or titles.
  - Any UTF-8 `.sql` file works as a saved query as it is. Opening or running
    a file never modifies it on disk. Unsupported encoding or a read failure
    is reported without replacing the tab's SQL.
  - Renaming a query in the interface renames its file, never over an
    existing file, and shows the name first when the title had to be made
    safe for a file name. Tags are edited in the interface and kept locally
    with the file reference; they do not travel with the files. External
    edits are reflected when the file is reloaded. Credentials, local paths,
    tags and connection bindings never go into the files.
  - Unsaved changes to SQL are visible. Closing a file-backed
    tab or the application offers saving, discarding or cancelling; a
    failed or cancelled save keeps the content and the unsaved state.
    Drafts and pending edits survive a failure through separate recovery
    files without overwriting the last explicitly saved script. Recovery
    does not restore results or database transactions.
  - An external change is detected before overwriting an opened file, and
    the user can cancel or choose how to resolve it. A failed or cancelled
    write leaves an existing destination intact. A moved or missing file
    is reported and can be reassociated while retaining its tags and
    connection association; it is never silently recreated or replaced with
    a different script.
  - Existing SQLite-backed saved queries are migrated to verified `.sql`
    files named by their titles, keeping their tags locally and preserving
    library identities, local connection associations and open-tab links.
    Migration handles filename collisions without overwriting files, reports
    the queries whose title changed to fit a file name, retains a
    recoverable backup and removes the old content only after successful
    verification. Partial failure is reported and can be retried without
    losing queries.
  - Opening, discovering, migrating or recovering files never executes SQL.
    File I/O and indexing run off the UI thread, follow the cancellation and
    feedback standards, and meet the applicable performance budgets. File
    size limits are documented and exceeded limits produce clear errors
    without silently truncating content.

### M8 — Reopen a closed query tab

- **Approval:** Approved on 2026-11-07.
- **Implementation:** Complete; see *Status* below.

Accidentally closing a query tab does not require reconstructing its SQL
and execution context.

- **Done when:**
  - **Reopen closed query tab**, also available through `Ctrl Shift T`,
    restores the most recently closed query tab's SQL, title, connection,
    context and parameter fields.
  - Repeated use reopens earlier closed query tabs from a bounded list for
    the current application session. Report tabs and recovery after restart
    are outside this milestone.
  - Restoring never executes SQL or claims to restore results, a transaction
    or the old database session. The next explicit run uses a new session.
  - A missing connection restores the SQL without a connection and explains
    what the user must select before running.
  - Existing confirmations for open transactions and running work still
    apply when closing; reopening does not imply that rolled-back work can
    be recovered.
- **Status:** Complete on 2026-11-07, Linux included (M5).
  `jykre::closed_tabs` keeps up to 20 closed query tabs of the session in
  memory (blank ones are not kept); **Reopen closed query tab** (`Ctrl
  Shift T`, and a title-bar button shown while one is kept) restores the
  newest with its SQL, title, connection, context, timeout and `:name`
  fields, runs nothing and says that results, the session and any
  transaction are not restored. A tab whose connection is gone reopens in a
  group without a connection with the existing warning; a link to a saved
  query removed meanwhile is dropped. Checked in the application on Windows
  (the button, a tab with a `:name` value, a tab of a deleted connection,
  the closing confirmations); `Ctrl Shift T` itself was not driven, since
  the check tooling cannot send modifier keys.

### M9 — Explorer favorites

- **Approval:** Approved on 2026-11-07.
- **Implementation:** Implemented; see *Status* below.

Frequently used connections, tables and views are reachable without
repeatedly navigating a deep metadata tree.

- **Done when:**
  - The user can add and remove a connection, table or view from a Favorites
    section through the explorer, with equivalent keyboard access.
  - Favorites survive a restart, remain associated with the same connection
    after a rename and use structural object paths rather than labels alone.
  - Listing and navigating favorites works from local state and the metadata
    cache without a server read. Opening a table or view follows the existing
    explicit **View data** behavior, including its execution safeguards.
  - An unavailable connection or object is clearly marked and can be removed;
    the application does not silently redirect a favorite to another object.
  - The list stays within the UI and metadata-access budgets in
    [Performance](../../standards/performance.md), using virtualization when
    its size requires it.
- **Status:** Implemented on 2026-11-07 and checked in the application on
  Windows the same day (adding a table and a connection from their menus,
  the section, opening a table as **View data**, a table renamed away
  marked **Unavailable** without redirecting, removing, and the favorites
  after a restart); `Shift F10` was not driven there. On Linux (M5) the
  favorites were also added from `Shift F10` and the arrow keys. `jykre::favorites`
  stores favorites under the `explorer.favorites` setting, by connection
  identity and structural path, keeping unknown keys and unreadable entries.
  The explorer's menus of a connection, table or view offer **Add to
  favorites** / **Remove from favorites** (`Shift F10` opens them from the
  keyboard); **Favorites**, above the connections, is a virtualized list
  whose rows the keyboard reaches. A table or view opens as **View data**; a
  connection is expanded and scrolled to. A favorite whose connection is
  gone, or whose object the connection's name index (read from the cache)
  no longer holds, is marked **Unavailable** and can be removed.

### M10 — Evidence for pending performance budgets

- **Approval:** Approved on 2026-11-07.
- **Implementation:** Measured on 2026-11-07; see *Status* below.

The daily-use claim includes measurements for the currently unmeasured
startup, idle-memory and export-responsiveness budgets.

- **Done when:**
  - On the reference Windows machine, a release build reaches an interactive
    window from a cold start within **1.5 s**, uses at most **200 MB** while
    idle with no connection, and has no UI-thread stall above **16 ms**
    while exporting.
  - Measurements use isolated configuration and synthetic data. The build,
    scenario, measurement method and results are recorded in
    [Performance](../../standards/performance.md), including enough context
    to repeat them. A missing measurement is never reported as a pass.
  - A result above a budget is fixed before this milestone closes; changing
    a budget still requires a maintainer decision under the performance
    standard.
- **Status:** Complete on 2026-11-08. Release build on the reference
  machine, isolated data folder, method and numbers in
  [Performance](../../standards/performance.md#startup-memory-and-export-measurements).
  Startup passes: 835 ms to a window that accepts input on the first launch
  of an empty data folder, 241–254 ms after; not measured after a reboot.
  Idle memory passes: 79.0 MB working set, 106.4 MB private bytes. Export
  responsiveness passes: timing `WM_NULL` round trips to the window, which
  has no system-timer floor (idle 1.7 ms at most), four 100,000-row CSV
  exports stalled the UI thread 6.3 ms at most while the file was written
  and 15.8 ms at most over the whole export, the native save dialog
  included (0.2.0-rc.1, 2026-11-08). The 2026-11-07 heartbeat could not
  tell this from its 16 ms floor.

### M11 — Automatic updates

- **Approval:** Scope addition approved by the maintainer on 2026-11-08,
  with [ADR-0033](../../adr/0033-update-check-and-signed-self-install.md)
  and its dependencies, accepted the same day.
- **Implementation:** Implemented on 2026-11-08; see *Status* below.

Users learn of a new version without visiting GitHub and install it from
the application, without trusting anything the maintainer's key did not
sign.

- **Done when:**
  - Once a day, on by default and off in **Preferences › About**, the
    application asks GitHub's release list, anonymously, whether a newer
    version exists (pre-releases included); **Check now** asks at once. The
    check never runs on the UI thread or during start-up.
  - A newer version shows in the status bar and in About. Nothing is
    downloaded or replaced without **Download and install**, which shows
    progress and can be cancelled.
  - Only an archive signed with the release key is installed; otherwise
    the application offers the release page. A failed or cancelled install
    leaves the running version, the data folder and the user's files as
    they were.
  - **Restart now** goes through the same confirmations as closing the
    window. Where self-install is not possible (a development build, a
    folder the user cannot write to, another platform), the update is
    offered as a link.
  - `release.yml` signs and verifies the archives before drafting; the
    signing key exists before the `v0.2.0` tag.
  - The flow is checked on Windows and Linux with signed release candidates.
- **Status:** Complete on 2026-11-08.
  `jykre::update` checks, verifies, unpacks and swaps with rollback;
  `src/app/updates.rs` draws Preferences › About › Updates and the status
  bar's badge and restarts through the close confirmations; `release.yml`
  signs and verifies. Tests run against a server on this computer with a
  test key. The maintainer's release key is committed (`6bb0990`) and the
  `ZIPSIGN_PRIVATE_KEY` secret is set in the `release` environment
  (2026-11-08). `v0.2.0-rc.1` signed and verified; its Windows archive
  carries the icon and version 0.2.0-rc.1. Checked end to end on
  2026-11-08 with the signed `v0.2.0-rc.3` (draft) and `v0.2.0-rc.4`
  (published pre-release), each from a new data folder: on Windows and on
  Linux (Ubuntu 24.04, Xvfb) rc.3 started without a warning, its
  automatic check found rc.4 after 30 s, the badge opened About,
  **Download and install** showed progress and installed it in the
  release folder, and **Restart now** started 0.2.0-rc.4 (the log's
  `started` with that version, the status bar without a badge). On
  Windows, closing the window, by a restart or not, logs GPUI errors about
  an invalid window handle, also before 0.2.0.
  Checked in the application on Linux (Xvfb, release build marked 0.0.9 in
  a release folder) on 2026-11-08: the automatic check after 30 s found
  the real v0.1.0, the badge opened About, **Download and install**
  downloaded it through GitHub's redirect with progress and **Cancel**, and
  the unsigned archive was refused with the folder unchanged; the toggle
  was saved and Tab reached the buttons. Windows and **Restart now** were
  not checked.

## Boundaries applying to every milestone

- No SQLite schema change in this scope without explicit approval.
- No new dependency or `[patch]` without maintainer approval; see
  [Stack and dependencies](../../standards/stack-and-dependencies.md).
- Driver contracts, schemas and ADRs change only with approval and a matching
  documentation update.
- The proposed additions do not authorize implementation, dependency changes,
  schema changes or ADR acceptance. Any required persistence design is reviewed
  before implementation under the existing approval rules.
- The added flows are checked in the application on Windows and Linux,
  including keyboard and focus where relevant. Result data is not persisted
  to support tab reopening or favorites.
