# Rust guidelines

`cargo xtask check` runs `rustfmt` and Clippy with warnings as errors. The
rest of this document is checked in review.

## Errors

### Structure

- Fallible operations return `DriverResult<T>` (`Result<T, DriverError>`).
  `DriverError` carries an `ErrorCode` and a message; the code is what callers
  and the UI branch on, never the message text.
- Each crate converts the errors of its libraries at its boundary (as
  `jykre-storage` does with `sql_error` and `json_error`). `sqlx::Error`,
  `reqwest::Error` and `keyring::Error` never appear in a public API.
- Drivers map their database's errors to the right code; see
  [Reliability](reliability.md#error-classification).

### Rules

- **No panics on production paths:** no `unwrap`, `expect`, `panic!`, `todo!`,
  `unimplemented!`, or indexing that can go out of bounds. Use `?`, `.get()`,
  `.ok_or(...)`. The only exception is an invariant that the surrounding code
  makes impossible to break; it gets a comment saying why (for example, an
  index just returned by a search on the same collection).
- **No swallowed errors.** `let _ = operation().await;` needs a comment saying
  why ignoring is safe (closing a connection that is already broken, a
  best-effort server-side cancel). The GPUI pattern `let _ = weak.update(...)`
  is accepted: it fails only when the view is already gone.
- **No `Result<T, String>` or `Box<dyn Error>`** in library APIs. `xtask` is a
  tool and may use strings.
- Error messages **never** contain credentials, tokens, SQL text, raw
  configuration or CLI output (see the comment on `DriverError`). A database's
  own error message may be passed through.

## Async

- Functions that do I/O are `async` and run on the Tokio runtime through
  `backend::run`. Inside async code, no blocking I/O (`std::fs` reads and
  writes, `std::net`, `std::process::Command::output`): use `tokio::fs` and
  `tokio::process`. Opening and `try_lock`-ing a lock file, which never waits,
  is accepted.
- Blocking libraries (the OS vault) run in `tokio::task::spawn_blocking`, as
  `jykre-secrets` does.
- CPU work above about 1 ms (converting a result, building an index, sorting
  thousands of items) does not run on the UI thread; see
  [Architecture](architecture.md#concurrency).
- Traits used as objects (`dyn Driver`, `dyn Session`, `dyn SecretStore`) use
  `#[async_trait]`, re-exported by `jykre-core`.
- A future never holds a `std::sync::MutexGuard`, a `RefCell` borrow or an
  `Rc` across `.await`.
- Every task has an owner. Tokio tasks are awaited or tied to a
  `CancellationToken`. Detached GPUI tasks (`cx.spawn(...).detach()`) hold
  only a `WeakEntity` and stop doing work once it is gone.
- Every network operation has an **explicit timeout**; do not rely on library
  defaults. Current values are listed in [Reliability](reliability.md#timeouts).
- Cancellable operations race the work against `token.cancelled()`, and the
  cancellation branch cleans up: it asks the server to cancel when possible
  and discards sessions in an unknown protocol state.

## Types and modelling

- **Newtypes for identifiers** (`ConnectionId`), so one ID cannot be passed
  where another is expected.
- **Enums for states**, never several booleans (`running`, `cancelled`, ...).
- Public enums that can grow (`DriverKind`, `ErrorCode`, `ObjectKind`) are
  `#[non_exhaustive]`.
- New fields of persisted structures get `#[serde(default)]` so existing local
  data keeps loading.
- Take `&str` and `&[T]` in parameters, return owned values. Avoid `clone()` of
  large collections in hot paths; share them with `Rc`/`Arc` instead.

## SQL generated by the application

The application generates SQL only for metadata introspection, previews and
session commands.

- Values are **always** bound parameters, never interpolated into the text.
- Identifiers that must appear in the text are quoted by the driver's quoting
  rules. Never `format!("SELECT * FROM {name}")` with an unquoted name.
- SQL typed by the user is sent **as written**. The application does not
  rewrite it (for example, it does not wrap it in `SELECT * FROM (...) LIMIT n`);
  the row limit is applied while reading.

## Secrets

- Every secret is a `secrecy::SecretString`. Call `expose_secret()` only at the
  exact point of use (building driver options, an HTTP header, the vault call).
- Types that hold secrets do not implement `Serialize`. `compile_fail`
  doctests in `jykre-core` guard `Credentials` and `ResolvedConnection`.

## Logs

There is no logging framework yet; [ADR-0009](adr/0009-structured-logging-and-timings.md)
proposes `tracing`. Until it is accepted, production code does not print to
stdout or stderr. When logging is added, the rules in
[Reliability](reliability.md#logs) apply.

## Documentation in code

- New or changed public items of the library crates get a `///` comment that
  states the contract: what they guarantee and when they fail.
- Comments explain **why** (constraints, database quirks, invariants), not
  **what** the next line does.

## Tests

- Unit tests in `#[cfg(test)] mod tests` in the same file, or in a sibling test
  file for large suites; integration tests in each crate's `tests/`.
- What must be tested and how is in [Testing](testing.md).

## Lints

[ADR-0011](adr/0011-workspace-lints.md) proposes enforcing these rules through
workspace lints shared by every crate:

```toml
[workspace.lints.rust]
unsafe_code = "forbid"

[workspace.lints.clippy]
unwrap_used = "deny"
expect_used = "deny"
panic = "deny"
todo = "deny"
dbg_macro = "deny"
print_stdout = "deny"
print_stderr = "deny"
await_holding_lock = "deny"
await_holding_refcell_ref = "deny"
```

Tests opt out of `unwrap_used`/`expect_used` with
`#[cfg_attr(test, allow(clippy::unwrap_used, clippy::expect_used))]`. A lint
is never silenced in production code to make the gate pass; an exception
needs the maintainer's approval and a comment.

## Checklist before reporting a task

- [ ] `cargo xtask check` passes.
- [ ] No new `unwrap`/`expect`/`panic` outside tests, except a commented invariant.
- [ ] No blocking I/O in async code and no data-sized work on the UI thread.
- [ ] Every new long operation can be cancelled and has a timeout.
- [ ] No secret in `Debug`, an error message, serialization or output.
- [ ] No library error type leaks through a public API.

## Known deviations

| Standard | Current code |
| --- | --- |
| Lints enforce the panic and print rules | No `[workspace.lints]` yet ([ADR-0011](adr/0011-workspace-lints.md), proposed) |
| No `unwrap`/`expect` outside tests, except commented invariants | A few uncommented invariant `unwrap`/`expect` calls remain in `src/app/mod.rs`, `src/app/sql.rs` and `src/grouped_tabs/mod.rs` |
| Operation state is an enum | `Workspace` uses several booleans for a run ([Architecture](architecture.md#known-deviations)) |
